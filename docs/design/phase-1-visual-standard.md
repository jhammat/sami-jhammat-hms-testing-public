# WonFlow Phase 1 Visual Standard

## Reception

The current Reception design is frozen and preserved.

Use new shared visual components only when they do not change Reception's
approved appearance.

## General direction

All other Phase 1 portals use:

- White and light-lavender backgrounds
- Blue, violet and cyan accents
- Clear page hierarchy
- Generous spacing
- Rounded cards
- Subtle shadows
- Strong typography
- Accessible contrast
- Visible keyboard focus
- Responsive layouts
- Calm healthcare-oriented presentation

## Surfaces

Primary cards:

- White background
- Soft slate or indigo border
- 20–26px corner radius
- Subtle shadow
- Clear header and content separation

Avoid:

- Heavy borders
- Excessive gradients
- Overuse of saturated colors
- Dense dashboard clutter

## Dashboards

A dashboard must remain professional when every value is zero.

Do not fabricate charts or activity.

Use:

- Zero-valued metric cards
- Empty chart states
- Configuration prompts
- Clear next actions

## Tables

Desktop tables must support:

- Clear header hierarchy
- Search and filters
- Keyboard focus
- Useful empty state
- Row actions
- Status indicators

Small-screen layouts may use:

- Horizontal container scrolling
- Responsive cards
- Priority-column reduction

Never allow viewport-level horizontal overflow.

## Forms

Forms use:

- Labels above controls
- Required markers
- Helpful hints
- Inline validation
- 44px minimum practical control height
- Clear primary and secondary actions
- Confirmation for destructive actions

## Avatars

Use:

- Uploaded profile photo when available
- Otherwise initials
- Circular shape
- Thin violet outline

## Hospital branding

Use:

- Uploaded hospital logo only after configuration
- Neutral hospital placeholder before configuration

Never preload a fictional hospital name or logo.

## Critical events

Deep red is reserved for:

- Security events
- High-risk access events
- Critical audit events
- Destructive confirmations
- Critical clinical-result indicators

Ordinary validation should use standard error styling rather than critical
audit styling.

## Motion

Use restrained motion.

The WonFlow W rotates during route changes.

Reduced-motion users receive a non-rotating or gently fading state.
